# Правила работы с HELPER

## Главное правило

**Перед отправкой (commit/push) внимательно изучать код.**

Проверять до пуша, а не после:

1. **Область видимости.** Каждая новая функция/вызов — где она объявлена?
   Глобальная или вложенная? Если вызываю из одного места, но она объявлена
   внутри другого колбэка — будет `ReferenceError` в рантайме.
   `node --check` этого не ловит: синтаксис верный, видимость нет.
2. **Что читает функция.** Все переменные в её условии (`MoneyMode`,
   `SessionNative`, `NativeBetIdx` …) объявлены и инициализированы к моменту
   вызова? Учесть TDZ для `let`.
3. **Реальный симптом, а не догадка.** Не «чинить» то, что кажется
   подозрительным: сверять с текущим кодом в файле, а не с памятью.
4. **Проверка до пуша.** `node --check js/application.js` + перечитать
   изменённый участок глазами (grep по имени функции — сколько определений
   осталось, одно или дубль).

Патч вида «добавил вызов не туда, где объявлена функция» уже случался:
`fmtNum` вызывал `modeNative()` из верхнего уровня, а та была вложена
в колбэк summary → «Extension error: modeNative is not defined» у всех
клиентов. Коммит `174a24d` чинил это.

## Цикл на каждое изменение

1. `node --check js/application.js`
2. Bump маркеров в `index.html`:
   - `style/style.css?v=YYYYMMDD-NN`
   - `js/application.js?v=YYYYMMDD-NN`
   - `<span class="ext-version">helper vYYYY-MM-DD-NN</span>`
3. В `FraudDetect.trex` — кэш-бастер `?r=NN-NN` (следующий номер).
4. commit → push в main.
5. Монитор деплоя GH Pages до `success`.

Дата в маркерах — **сегодняшняя**, не прошлая.

## Технические правила

- Патчи делать **файловыми node-скриптами** (норма `\r\n` → `\n`); рабочая
  копия CRLF, `edit`-tool ненадёжен. Проверять `count` замен — при
  `anchor count != 1` патч не выполнять.
- Якоря с бэктиками — через `String.fromCharCode(96)`.
- Числа в UI — через `fmtNum`; в финансовых карточках Bet/Net всегда
  `fmtNum(..., 2)`.
- `fmtNum` без явных цифр: EUR всегда с копейками; native от `100,000` —
  без копеек; явный `digits` никогда не переопределять.
- Дедупликацию по Player+Round ID не возвращать; skip в «Bet continuity»
  считать по числу gap'ов.
- Клик-копирование round id в Tableau-вебвью не чинить (clipboard
  заблокирован).
- Старые GitHub deployments не удалять; Bootstrap JS CDN не удалять.
- Рулеточный тул и Opposite Betting tool — не трогать.
